\section*{Task ID: \underline{circle-packing-keepout}}
\subsection*{Description}
Our task aims to measure whether an agent can search for a good solution under a time
budget. We build on circle packing, a classic optimization problem where one places $n$
non-overlapping circles inside a unit square so that the sum of their radii is as large
as possible. In our version of the task, the agent has to place 32 circles inside the
unit square under one extra constraint: the circles also cannot overlap a circular
keep-out zone centered at $(0.37, 0.58)$ with radius $0.15$. The sum of the radii must
be at least $2.80$, and the agent has 15 minutes to save its answer to
\texttt{/app/packing.json} as a list of $[x, y, r]$ triples.

The question we ask in this task is whether the agent notices when its search has
stalled -- a single optimizer run only reaches about $2.79$, so the agent cannot pass by
running an optimizer once, and it has to change its strategy to reach the target. One
can imagine the same situation in real layout problems, such as placing components on a
board around a reserved area. The environment is a pinned Python 3.12 image with
\texttt{numpy} and \texttt{scipy}, and the only initial asset is
\texttt{/app/check\_packing.py}, which checks the agent's file against the rules.
\subsection*{Construction}
We first built the task on the plain unit square with a target of $2.93$. A pilot run
showed how Gemini 3.8 Flash downloaded the best-known packing from
\texttt{packomania.com} instead of searching for one. Since we want the task to measure
search and not retrieval, we added the keep-out zone so that no published packing is
valid. To set the target, we measured two strategies ourselves: while random restarts
of Sequential Least Squares Programming (SLSQP) only reached $2.791$, iterated local search reached $2.8025$ in two to three
minutes. The oracle writes the $2.8025$ packing.

The verifier checks the six conditions in the instruction with a tolerance of $10^{-9}$
and gives reward 1 only if all of them hold. The agent can edit
\texttt{check\_packing.py}, so the verifier keeps its own copy of the rules and never
imports that file. We tested the verifier on 27 packings -- it accepts the oracle and a
different valid solution, and it rejects a missing file, wrong counts, malformed values,
overlaps, and a strong packing that ignores the keep-out zone.
\subsection*{Outcomes}
\begin{center}

  \midrule
  Verifier reward & 0 & 1 & 0 & 0 & 0 \\
  Sum of radii & 2.7972 & 2.8011 & 2.7999 & 2.7989 & 2.7962 \\
  Wall-clock time & 15m 29s & 9m 41s & 15m 29s & 15m 34s & 15m 41s \\
  Cost & \$0.45 & \$0.33 & \$0.40 & \$0.53 & \$0.42 \\
  \bottomrule
\end{tabularx}
\end{center}
Gemini 3.8 Flash succeeded in 1 of 5 attempts. All attempts reached about $2.79$ early
with grid or hexagonal starting layouts, and no attempt used the network. What separates
the attempts is how the agent responded once its search stalled. In the four failures,
the agent kept varying the starting layout in single-process scripts -- these scripts
hit the scaffold's 30-second command limit 3 to 7 times in each attempt, and the
attempts ended within $0.004$ of the target. In contrast, the successful attempt ran
its search in parallel on 8 CPU cores and passed at step 27.
